# The .solution-factory folder

Everything Solution Factory knows about a project is stored as plain files in
`.solution-factory/` at the project root. Commit it to git.

```
.solution-factory/
  config.json          your settings
  manifest.json        project name, description, schema version
  sequence.json        the master ledger: story order, status, dependencies
  decisions/           adr-001.md ...      architecture decision records
  constraints/         const-001.md ...    hard limits
  docs/                requirements.md, architecture.md
  context/capsules/    short topic summaries, generated
  ideas/               IDEA-001/ ...       idea.md and (once planned) plan.md
  epics/
    epic-01/
      epic-01.json     epic definition and run state
      stories/
        backlog/       not started
        active/        in progress
          01.003/
            01.003.json   the story
            plan.md       the implementation plan
            local.md      discoveries and blockers noted during the work
        done/          completed
        deferred/      set aside
  tests/               demo scripts per story (only if enabled)
```

## Decisions and constraints

- **Decisions** (`adr-NNN`) record an architectural choice with its context
  and consequences.
- **Constraints** (`const-NNN`) record something the project must respect:
  a technology limit, a compliance rule, an integration contract.

Every story lists the decisions and constraints that apply to it. Plans are
written against them, and the code reviewer checks the change against them.

You can edit these files by hand. Keeping them accurate is the single most
effective way to improve results.

## Capsules

Capsules are short summaries that group related decisions and constraints by
topic (authentication, data persistence, testing strategy, and so on). They
are generated by a script and loaded per story so Claude gets the relevant
context without reading every file. They are regenerated automatically when
decisions or constraints change — do not edit them by hand.

## Stories

A story is a JSON file with:

| Field | Meaning |
|---|---|
| `id` | `<epic>.<story>`, e.g. `01.003`. Numbers only |
| `title`, `goal` | What the story delivers |
| `acceptance` | The acceptance criteria |
| `complexity` | 1 up to the configured threshold |
| `dependencies` | Story IDs that must be done first |
| `outputs` | Files the story expects to `create` and `modify` — used to decide which stories can run at the same time |
| `decisions`, `constraints`, `context` | The decisions, constraints and capsules that apply |

A story's status is the folder it sits in — `backlog`, `active`, `done` or
`deferred` — and the same status is recorded in `sequence.json`. The scripts
move the folder and update the ledger together, so the two cannot disagree.

**Execution order is the order of entries in `sequence.json`**, not the
numeric order of the IDs. Stories inserted later can have higher numbers and
still run earlier.

## Discoveries

While implementing, anything learned that future work should know — an
unexpected constraint, a pattern that had to be adopted — is noted in the
story's `local.md`. When the story completes, each discovery is scored for
relevance and then:

- added as a new decision or constraint,
- merged into an existing one it extends or corrects, or
- dropped as too narrow.

The thresholds are in `config.json` under `relevance`. This is how the project
context improves as work proceeds.

## Ideas

Each idea is a folder `ideas/IDEA-NNN/` with an `idea.md` and, once planned, a
`plan.md` holding its technical approach. An idea's state is one of
`raw`, `triaged`, `planning`, `planned`, `promoted`, `discarded`. A promoted
idea has become an epic; from then on the epic is the source of truth.

## Epic run state

When `/solution epic` runs, the epic's JSON gains a `run` block recording
whether the run is active, stopped or complete, and in which mode. That is
what `/solution next` reads to resume a paused run.

## What lands in your repository

| Where | What |
|---|---|
| `.solution-factory/` | Committed as work proceeds |
| `feature/<story-id>-<slug>` branches | One per story; merged with a merge commit and deleted on completion |
| `.sf-worktrees/` | Temporary worktrees for concurrent epic runs. Excluded from git locally and removed when the run ends |

Solution Factory never pushes to a remote.
